# 検証と入出力の規則

## 新機能には必ず検証ケースを付ける

- `data/sample/` に**解析解と比較できる**ケースを追加し、
  `data/sample/rlc_check.sh` に比較を足して CI (3 OS) で回します。
- 許容誤差は「測った値」ではなく**物理的な根拠**で決めること
  (1 次元厳密 → 1%、円形導体の階段近似 → 5% など)。ケースのコメントに
  期待値の導出を書きます。
- 期待値は awk で計算できる形に落とすか、`.ofe` のコメントに導出を残して
  スクリプトへ定数で埋め込みます。

## 自己検証は「その検査で落ちる誤りは何か」を先に決める

閉形式と一致した = 検査できている、ではありません。実際に踏んだ例:

- **一様場は数値積分の誤りを検出できない。** 最低次 Nedelec 補間は一様場に
  対して要素内で定数になるので、質量行列を 1 点 (重心) 則に置き換えて
  階数が 6 → 3 に落ちても `uᵀTu` は 3e-16 で合格します。質量行列の検査は
  **空間変化する場**で行うこと (それでいて補間が厳密な場、例えば回転場
  E = ½(a×r) が {a + b×r} に入る、を選ぶと機械精度の恒等式になります)。
- **軸に平行な試験場はテンソルの 1 成分しか見ない。** 回転場を ẑ 方向に
  とると期待値が Σ ν_zz V になり、ν_xx / ν_yy をいくら壊しても落ちません。
  試験場の向きは **軸に平行でない向き (1,2,3)** にとり、期待値を
  Σ (aᵀν a) V の二次形式で書くこと。
- **等方性材料だけで回すとテンソルの非対角項は死んだコードになる。**
  ν の非対角成分が恒等的に 0 なので、成分順序 (xx,yy,zz,xy,yz,zx) の
  取り違えや係数 2 の欠落が一度も実行されません。異方性ケース
  (`edge_test_aniso.ofe`) を必ず対にすること。
- **計算した診断値を捨てない。** `(void)tdif;` のように片方だけ表示して
  合否に使わないと、その検査は存在しないのと同じです。

- **既定で通らない経路 (opt-in のキー) も検証ケースを持つこと。** `gauge = 1` は
  既定が 0 なので、サンプルに 1 を置かないと該当コードが一度も実行されません。
  実測: 木の awall 優先処理を丸ごと壊しても全ケースが緑のまま、`gauge = 1` の結果
  だけが L −46% になりました。既定値と非既定値の両方を回すこと。
- **材料パラメータは「既定値以外」で必ず 1 ケース回すこと。** μr を使う経路が
  μr = 1 のケースしか無かったため、ν を 1/μ0 に固定する変異が全緑で通りました
  (磁性導体で L が −98%)。
- **診断・警告そのものも検査対象。** 「警告が出るべきケースで出るか」を
  ログの grep で assert しないと、診断式の誤りは永久に気づけません。

- **1 つの格子に材料が 1 種類しか無いケースは、要素毎の材料参照を検査できない。**
  実測: `material_coef_pub(m, ...)` を `(2, ...)` に固定する変異は、単一材料の
  `bar_eddy` を −0.12% (許容内) で素通りし、導体+空気の `bar_air` でだけ +93.7%
  で落ちた。**2 種類以上の材料が同居するケースを 1 つは持つこと。**

- **掃引は「各点が個別実行と完全一致すること」を検査する。** 閉形式との比較だけ
  では掃引間の状態の漏れを捕まえられない。実測: 分散材料の再展開が効かず C が
  最初の周波数で凍結する不具合が、この一致検査でだけ落ちた。
- **禁止の組み合わせを検査するときは、他の検査に引っかからない入力にすること。**
  実測: `currentsweep` を `ja` 無しで書いたら「ja が要る」という別の検査で
  弾かれ、併用禁止を外しても検査が通ってしまった。

- **エネルギー / 大きさの恒等式はベクトルの向きを検査できない。** ∇×(u ẑ) を
  −∇u に取り違えても 90 度回るだけで |B| は変わらず、∫|B|² の恒等式は素通りする。
  形状の対称性から向きが決まる場合はそれを別に assert すること
  (実測: 板が x に一様なら B は x 向き、という比較でだけ落ちた)。
- **複素場は実部と虚部の両方が効く恒等式を選ぶ。** |J|² だけでは虚部の符号反転が
  見えない。符号つきの ∫J dA を端子アドミタンスと比べると落ちる。

- **要素内の評価点は一様な場では検証できない。** 場の出力は要素あたり 1 本の
  ベクトルなので重心で評価するが、一様な場では要素内のどこで取っても同じ値に
  なる。実測: 平行平板の場の出力だけでは、評価点を重心から頂点にずらす変異が
  素通りした。空間変化する場を使う恒等式 (2 次の φ に対する ∇φ = a + B r) で
  別に assert すること。
- **高い次数の要素は「低い次数と有意に違う」ことを対で検査する。** 閉形式との
  比較だけでは、2 次要素が黙って 1 次に退行しても許容を緩めれば両方通る。
  同じ格子・同じ材料で次数だけ落とした対照ケースを置き、誤差の比を assert する
  (実測: 粗い同軸で 1 次 +2.99% に対し 2 次 +0.087%、比 34.5)。
- **等パラメトリック写像は「積分した体積」で直接検証できる。** 場の精度は
  離散化誤差と混ざるが、体積は解析値と比較できて次数もはっきり出る
  (実測: 円環で h^4、比が 16 で揃う)。頂点だけで積分すると内接多角形の体積に
  なるので 290 倍ずれる。
- **交番する離散化の誤差は最大値では見えるが平均では消える。** 四角形を対角線で
  2 つの三角形に割ると、片方向にしか変化しない場でも重心での直交方向の勾配が
  対角線の向きに応じて交番する (実測: max|B_z| が max|B_y| の 0.9%、符号つき
  平均では 1e-11)。向きの検査は**符号つきの体積加重平均**で書くこと。
- **形式の検査 (VTK のセル型など) は値の検査と別に置く。** `vtkcheck.awk` は
  セルの節点数で図形を判定するので、セル型の値が違っても値の恒等式は全部通る。
  ファイルが開けなくなる誤りは型そのものを assert しないと捕まらない。
- **「正しいが遅い」変異は値の一致では捕まらない。** 直接解法の並べ替え (RCM) を
  無効にしても答えは正しいままなので、9 ケースの完全一致が全部通った。
  性能のための仕組みは**性能そのものを assert する** (平均帯幅が節点数の
  1/4 未満、等)。
- **同じ物理を別の書き方で 2 通り与えて一致を見るのが最も厳密。** 入力形式を
  足したときは「同じ形状を新旧の形式で書いた結果がバイト単位で一致すること」を
  恒等式にする (閉形式が要らず、許容誤差の議論も要らない)。
- **形式の分岐は「その分岐を通るファイル」が無いと死んだコードになる。**
  実測: Gmsh 4.1 の `$Entities` は点だけ項目数が違うが、検証用に書き出した
  ファイルに点エンティティが無かったため、その分岐を壊す変異が素通りした。
  実際のツールが出す形に寄せること。
- **閉形式が無くても「合同性」は厳密な恒等式になる。** 格子を面内で任意角だけ
  回すと (位相は変えずに節点座標だけ回す)、材料テンソルを同じ角で回した問題は
  元と**合同な離散問題**になるので、答えは全桁一致しなければならない。
  実測: 異方性 ν の非対角成分はこれ以外の方法では一度も実行されなかった
  (1 次元解では ∂Az/∂p = 0 で効かず、同軸は回転対称なのでテンソルを回しても
  答えが変わらない)。斜めに回した非対称断面だけが効く。
  対照として「非対角を落とすと必ずずれること」も同時に assert すること。
- **閉形式の右辺が格子の形に依存していないか確かめる。** 曲がった格子で
  「頂点 4 個から作った四面体の体積」を使うと、正しい実装が 4.7% で落ちる
  偽陽性になった。検査が落ちたときは実装を疑う前に期待値の導出を読み直すこと。

- **同じ値を 2 つの出口に出すなら、出口どうしの一致を恒等式にする。** 系列の
  HDF5 出力は `ofe_sweep.csv` / `ofe.log` の履歴表 / `ofe_field.vtk` と同じ数字を
  持つので、閉形式を持ち出さずに「食い違わないこと」だけ見れば足ります
  (一番起きやすい壊れ方がまさにそれ)。
- **テキストで比べるときは桁を相手に合わせること。** csv は `%.8e`、VTK は
  `%.9e`、ログは `%13.6e` で書かれています。取り出しと比較で桁が違うと
  二重丸めで最後の桁がずれ、**正しい実装が落ちます** (実際に踏んだ)。
- **一様な誘電体の周波数掃引では φ が周波数に依らない。** ε が一様なら
  ∇・(ε∇φ) = 0 の解は ε に依らず、変わるのは C だけです。「掃引の点ごとに場が
  違う」ことを検査したいときは、表皮効果のある `F` の掃引を使うこと。
- **空のファイルを `awk` の `NR == FNR` に食わせない。** 1 つ目が空だと 2 つ目が
  1 つ目として読まれ、件数の報告が入れ替わって診断が嘘になります。
  シェル側で `[ -s ... ]` を見てから渡すこと。

- **「弾かれること」だけでは検査にならない。理由まで grep すること。** 実測:
  バイナリ格子のエンディアン検査を丸ごと外しても、逆エンディアンのファイルは
  別の理由 (節点が少なすぎる) で落ちるため `rejected -> OK` のままでした。
- **バイナリ形式の検証用ファイルは本物のツールに作らせる。** 自前で書き出すと、
  書き手と読み手が同じ誤解を共有したときに素通りします。gmsh なら
  `gmsh -0 <格子> -o <出力> -format msh22|msh41 -bin`。
  **gmsh は変換のたびに節点を振り直す**ので、比較する ASCII 側も同じ変換で
  出したものを置くこと (元の格子と直接比べると丸めの順序が変わって一致しない)。
- **バイナリのファイルは `.gitattributes` で `-text` にする。** Windows で
  チェックアウトすると改行が変換されて壊れます。

- **アフィンな要素では等パラメトリック写像の手抜きが検出できない。** 平行六面体
  ではヤコビアンが要素内で一定なので、「J を要素中心で 1 回だけ評価する」誤りが
  厳密に正しくなります。実測: 直方体・剛体回転・同軸のいずれでも答えが 1 桁も
  動かず、**ゆがんだ格子**でだけ 4.7% ずれました。回転対称なケース (同軸) も
  効きません — 解が θ に依らないので、要素行列が 3% 違っても相殺します。
- **編集とビルドが同じ秒に収まると `make` が再コンパイルを飛ばす。** 変異解析で
  「変異させたのに答えが変わらない」ときは、まず `md5sum` でバイナリが変わったか
  確かめること (実測: 古いバイナリで測って「等価変異だ」と誤診しかけた)。
  対象の `.o` を消してからビルドすれば確実です。

新しい検査を足したら**わざと壊して落ちることを確認する** (変異解析)。
落ちなければその検査は無意味です。README の検出能力の表を更新すること。

## 入力キーの追加

- `sol/input_data.c` に追加し、既定値は「**キー省略時に従来動作と完全一致**」
  になるよう初期化します (後方互換)。
- 材料番号を参照するキー (`mur` / `tand` / `debye` など) は `material` 行より
  後に書く必要がある旨を README に明記します。

## 出力の互換

- `ofe.out` のフォーマットを変えたら先頭のマジック (`OFEOUT0n`) を上げ、
  `post/post_Main.c` を必ず追従させます。
- `ofe_post` が新しいフィールドを無害に扱えることを確認すること。

## CI

`.github/workflows/ci.yml` は Linux / macOS (libomp) / Windows (MSVC + Ninja) の 3 OS。
既定のビルドに外部ライブラリ依存はありません (HDF5 のみ任意依存で、
`WITH_HDF5=ON` の Linux ジョブが 1 つ別にあります)。
Windows の検証ステップは Git for Windows の
bash で `rlc_check.sh` を実行します。タグ `v*` push で Release にバイナリを添付。

CI を落としたまま次の作業に進まないこと。Windows だけ落ちた場合は
`.claude/rules/portability.md` を先に読み直します。
